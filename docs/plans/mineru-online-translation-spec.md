## Problem Statement

I can reconstruct an authorized five-page MinerU recognition sample as a source-language PDF or EPUB, but I cannot yet use the existing Web application to turn a scanned, mixed, or text PDF into a translated book through MinerU online recognition. The current PDF translation workflow depends on native text extraction, while the online workflow is a manual probe and its cached output is explicitly a reconstruction preview, not a translated book.

For personal use, I need one predictable PDF workflow that preserves readable book content and images, can continue after a short local wait or restart without silently submitting the book again, and reports incomplete work honestly. I do not need a choice of recognition engines, original-page replication, a billing platform, or commercial compliance screens.

## Solution

Make MinerU online recognition the only recognition path for PDF translation in the existing Web application. Keep a brief task-level confirmation before sending the PDF to MinerU, use the account token configured by the operator, and feed the validated recognition result into the existing translation and reflowed-PDF generation pipeline.

The first release produces a downloadable translated PDF with whole-book coverage, stable text/image ordering, and an accounting report. Independently recognized captions and footnotes are translated. Tables and formulas may remain source images, and text in image pixels is not redrawn; source-preserved content is clearly identified as untranslated. Unsupported content that cannot be reliably preserved causes an explicit failure rather than a silent omission.

Recognition has a five-minute local budget per attempt or continuation. A local recognition pause preserves known task state and allows safe continuation of the existing remote task where its identity and phase permit. It does not imply remote cancellation or trigger an automatic replacement submission. Working data follows the existing task recovery and cleanup lifecycle, and new Web strings update immediately across all seven supported UI languages.

## User Stories

1. As a reader, I want one online recognition path for every PDF, so that I do not have to choose between local extraction and online recognition.
2. As a reader, I want scanned and mixed PDFs to be accepted without requiring a native text layer, so that the workflow supports the books I actually have.
3. As a reader, I want choosing or uploading a file to this application to be distinct from sending it to MinerU, so that selecting a document does not grant unintended third-party upload permission.
4. As a reader, I want one brief upload confirmation for each task, so that I can authorize online recognition without navigating long policy dialogs.
5. As an API caller, I want the same explicit authorization rule as the Web interface, so that another entrypoint cannot silently bypass my upload decision.
6. As an operator, I want to use the MinerU token from the existing environment configuration, so that I do not need a new key-management page or a separate account system.
7. As an operator, I want a useful missing-configuration error before any provider request, so that I can correct the setup without wasting remote work.
8. As a reader, I want page and byte limits checked before provider submission, so that an oversized book is rejected clearly rather than partially uploaded or silently split.
9. As a reader, I want corrupt or password-protected PDFs rejected clearly before submission, so that I can correct the source document first.
10. As a reader, I want progress to distinguish recognition from translation and output generation, so that queued or submitted recognition is not mistaken for a finished book.
11. As a reader, I want recognition to pause locally after five minutes, so that a slow remote task does not keep this attempt waiting indefinitely.
12. As a reader, I want stopping to prevent further local processing and translation, so that the application respects my decision without falsely claiming it stopped the provider.
13. As a reader, I want Continue to query my existing recognition task, so that I do not silently upload or request recognition of the same book again.
14. As a reader, I want a restart to preserve known recognition identity and validated results, so that work can continue when the provider's contract and saved phase allow it.
15. As a reader, I want changed source files or incompatible results detected before translation resumes, so that saved translations are never attached to different paragraphs.
16. As a reader, I want an uncertain submission outcome explained without automatic resubmission, so that a lost response does not create unexpected duplicate remote work.
17. As a reader, I want an interrupted upload that cannot safely continue reported honestly, so that a saved task identifier is not presented as a guarantee of automatic recovery.
18. As a reader, I want repeated Continue requests to leave only one active execution of my task, so that accidental clicks or concurrent requests do not duplicate submissions.
19. As a reader, I want legacy native-extraction checkpoints preserved but not silently applied to new recognition results, so that an upgrade does not corrupt or destroy previous work.
20. As a reader, I want headings and reading order preserved in the translated rendition, so that the book remains coherent even when pagination changes.
21. As a reader, I want every recognized image kept at its intended reading position, including before the first paragraph, so that figures do not disappear or drift.
22. As a reader, I want translated captions and footnotes to stay associated with their figures or surrounding content, so that their meaning remains understandable.
23. As a reader, I want tables preserved as readable source images when semantic reconstruction is unavailable, so that the original information remains present.
24. As a reader, I want formulas and image-embedded text preserved without speculative redrawing, so that the application does not invent or damage visual content.
25. As a reader, I want source-preserved content explicitly identified as untranslated, so that whole-book coverage is not confused with translation of every visible word.
26. As a reader, I want unsupported or unreliable structures to cause a visible failure rather than omission, so that an incomplete rendition cannot appear successful.
27. As a reader, I want every expected source page represented in recognition coverage, so that a small sample cannot masquerade as the complete book.
28. As a reviewer, I want each recognized block retained or excluded with a reason, so that I can inspect content accounting rather than trust output page counts.
29. As a reader, I want the existing language, translation, and bilingual options to continue working where applicable, so that adding recognition does not create a second translation workflow.
30. As a reader, I want the finished book to exclude preview notices and preview metadata, so that it is not labeled as an untranslated sample.
31. As a reader, I want bibliographic metadata to avoid invented authorship, so that body text is not published as an assumed author name.
32. As a reader, I want a downloadable PDF only after the output has been generated and validated, so that submission success or a missing artifact cannot be reported as completion.
33. As a reader, I want failed or unfinished translation chunks to remain partial and resumable, so that source-text fallbacks are not misrepresented as a fully successful translation.
34. As a reader, I want deliberately source-preserved tables and formulas accounted for separately from failed translation chunks, so that the agreed content policy is not confused with a translation error.
35. As an operator, I want recognition working files pruned after validated, non-resumable success, so that completed tasks do not create a permanent recognition archive.
36. As a reader, I want paused, failed, and partial tasks to keep the data needed for safe recovery, so that cleanup does not remove my only way to continue.
37. As an operator, I want recognition recovery data to follow existing task deletion and 30-day startup cleanup, so that I do not need a second cleanup service or a misleading exact-expiry promise.
38. As a reader, I want task cleanup to leave finished outputs and private reference evidence under their existing ownership rules, so that deleting working data does not destroy unrelated files.
39. As a reader, I want authorization, progress, pause, continuation, and error text to update when I switch UI language, so that I do not have to reload the page or interpret stale-language controls.
40. As an operator, I want credentials and signed storage URLs kept out of browser payloads, logs, and checkpoints, so that the new workflow does not leak access capabilities.
41. As a reader, I want non-PDF workflows to retain their existing behavior, so that this PDF integration does not disrupt other book formats.
42. As an operator, I want offline tests to exercise the complete application workflow without credentials, private books, or live provider calls, so that development and automated checks cannot consume my account usage.
43. As a reviewer, I want separately authorized sample and whole-book acceptance runs with recorded limitations, so that mocked success is not presented as evidence of real recognition or translation quality.

## Implementation Decisions

- **One recognition path, existing translation pipeline.** Replace the PDF extraction boundary with online recognition. Reuse the shared plain-text translation pipeline and PDF builder. Do not introduce another translator, renderer, generic recognition-provider hierarchy, or local fallback. Local PDF validation, source-image cropping, and rendering remain valid internal operations, not a local recognition mode.
- **Brief authorization at the actual trust boundary.** Require an explicit task-level authorization signal before provider submission, validate it server-side and in the core submission path, and bind it to the task's source identity. Missing consent cannot default to permission. Restore consent only for the same previously authorized task and source; a continuation must not implicitly authorize a replacement submission.
- **Configuration and scope.** Resolve the MinerU token through the existing environment bootstrap. Keep it server-side, separate from the LLM provider selector. The configured account bears its usage. Personal use does not add commercial approval gates, long warning screens, billing, or multi-user secrets management; status text must still be truthful.
- **Limits.** The recognition ceiling is 200 pages and 200,000,000 bytes, with stricter existing admission limits retained. The current secure Web uploader limits input to 100 MiB, so that remains the effective Web byte ceiling; this spec does not raise the global upload limit. The 198-page reference PDF of 50,634,055 bytes fits both ceilings. Reject excess before contacting MinerU; do not split or partially submit the book.
- **Online HTTP contract.** Use the installed HTTP client and verified standard MinerU upload, polling, and result-download contract. Treat HTTP success and provider application success separately, check returned shapes and task identity, and keep provider authentication off separate storage requests. Reuse archive/path/image resource protections and allow only verified download/upload destinations. Do not import the manual probe script as production infrastructure or use the lightweight service as a whole-book substitute.
- **Preview-neutral source adaptation.** Separate source content from preview decoration at the reconstruction boundary. Preserve the existing offline preview behavior and provenance compatibility, but never remove the first paragraph or repair indices ad hoc in the translator. Production output and prompts must not contain the preview notice or suffix, and metadata must not publish a heuristically inferred author.
- **Complete, stable content identity.** Bind results to the source fingerprint, recognition parameters, page mapping, and validated result identity. Whole-book recognition must cover exactly the expected source pages, including empty recognized pages where applicable. Resume translated segments only against compatible source content and paragraph mapping; matching paragraph counts alone is not sufficient. Preserve incompatible legacy checkpoints and report the mismatch rather than overwriting them.
- **Task-owned durable state.** Extend the existing job/checkpoint owner with atomically updated recognition state: source identity, phase, known remote identifiers, and validated result identity. Keep it within existing task-owned recovery storage and its deletion lifecycle. Do not create a second database, queue, or permanent cross-task cache, and do not persist credentials or signed storage URLs in recovery state.
- **Five-minute local budget.** Each recognition attempt or manual continuation has a 300-second local budget, including transfer and polling but excluding subsequent translation. Retries share the same deadline; they do not reset it. Bound individual network operations by the remaining budget, and use finite retries only where operation safety is established. A continuation may grant a new local waiting budget while retaining the same remote task.
- **Safe pause, restart, and ambiguity.** Reuse existing pause/interruption and resumption concepts. A local stop prevents subsequent local work and translation but does not imply remote cancellation, deletion, or avoided usage. Ensure one active execution per job. If submission may have succeeded but no identifier is known, retain an explicit unknown outcome and do not resubmit. If an incomplete upload cannot recover its transient URL through the verified contract, report the saved phase and limitation instead of claiming automatic recovery or creating a replacement task.
- **Source-preserved complex content.** Extend the same online V2 adapter only for contract-backed table/formula representations. Use supplied assets or source-PDF crops only when source identity, page geometry, and bounds can be established reliably. Preserve reading position, caption/note association, and provenance. Unsupported or unreliable blocks fail explicitly. Inline formulas are not claimed as supported without a verified representation and preservation path.
- **Honest completion and output ownership.** Publish a valid reflowed PDF and a durable accounting report/sidecar outside the pruned working cache. Preserve the existing distinction between successful, partial, interrupted, and failed work; unfinished body translation remains resumable. Source-preserved content is identified and counted separately, not treated as proof that every visible word was translated. Do not equate submission, elapsed budget, or partial page coverage with completion.
- **Cleanup.** Attach recognition working files to the existing task lifecycle. Prune only when successful completion is validated and no recovery retention rule applies; retain them for interrupted, failed, or partial work. Extend existing explicit task deletion and 30-day startup cleanup rather than adding a scheduler. Do not automatically expire finished outputs or modify historical probe/acceptance evidence.
- **Minimal Web changes.** Reuse task creation, status, interruption, continuation, and artifact-download surfaces. Add brief PDF authorization, recognition-phase progress, actionable failures, and local-stop/continue semantics; do not add a recognition selector or token editor. Resolve error categories into reactive localized UI text, with all keys and interpolation placeholders synchronized across English, French, Spanish, German, Simplified Chinese, Japanese, and Korean. Non-PDF workflows remain unchanged.

## Testing Decisions

- **Confirmed primary acceptance seam:** exercise the existing Web/API task lifecycle from local upload and authorized task creation through status, interruption/continuation where applicable, and artifact download. Use real routing, source validation, task-owned temporary storage, SQLite recovery, online-result adaptation, translation orchestration, and PDF generation. Substitute only the external MinerU HTTP transport, external LLM client, and time. Do not mock the reconstruction adapter, shared translation pipeline, PDF builder, or an invented middle-layer success result.
- **Assert externally meaningful behavior.** Inspect responses, observable task states, outgoing provider requests, actual downloaded PDF text/images/metadata, accounting output, and retained or deleted task-owned files. Avoid tests tied to private helper call order, arbitrary internal record layout, or a new test-only API. Use temporary databases and generated synthetic PDFs/assets; private reference files and credentials are never automated-test dependencies.
- **Success and admission cases.** Cover text, scanned, and mixed inputs; explicit consent and missing consent; missing configuration; encrypted/corrupt PDFs; effective page/byte limits; complete versus sample-only page coverage; leading and adjacent images; headings/captions/footnotes; source-preserved blocks; output validity; preview-artifact absence; and isolation of non-PDF workflows. Unauthorized or invalid cases must make zero provider requests.
- **Failure, timing, and restart cases.** With a fake monotonic clock and scripted provider responses, cover the 300-second deadline, bounded rate-limit/transient retries, application errors under HTTP 200, known-ID continuation, process-state restoration, duplicate continuation, changed source, incompatible checkpoints, uncertain submission, and an upload that cannot safely resume. Verify no automatic replacement submission, no false completion, and no subsequent translation after a local recognition stop. Check cleanup separately for completed, partial, failed, interrupted, explicitly deleted, and expired tasks.
- **Small supporting contract tests only where useful.** Exercise the online client's public operation with the installed HTTP client's mock transport for malformed payloads, credential separation, destination/redirect checks, and unsafe or excessive archives/assets. Reuse synthetic V2 fixtures for loader/adapter edge cases. Establish table/formula fixtures from the actual online contract rather than inventing unsupported shapes. These are supporting checks, not additional application entrypoints or service abstractions.
- **Prior art.** Reuse the existing synthetic MinerU cache and fingerprint fixtures, real-PDF translator/builder tests, isolated checkpoint/job-history fixtures, upload-security cases, secret-stripping checks, and the progress contract's fake-clock pattern. Update old native-extraction-only translator expectations to the intentional online-only behavior; retain native extractor and builder regression coverage where still applicable.
- **UI and live proof.** Check seven-locale key and interpolation parity, then switch language while authorization, progress, pause, and error states are displayed and verify immediate updates without reload. Do not introduce a browser framework solely for this feature. Run focused tests, existing MinerU and PDF regressions, and the configured offline project gate; the PDF suite must be invoked explicitly rather than assumed to be included. Only after separate authorization, perform a bounded live sample and then the 198-page book, recording machine accounting and the actual representative visual review performed. A five-minute pause is a valid resumable result, not permission to extend the budget or resubmit.

## Out of Scope

- A local/native/OCR recognition selector or fallback for this PDF workflow.
- Geometric replication, source-identical pagination, or original-layout image-text redrawing.
- Semantic/editable table reconstruction, guaranteed translation inside source-preserved images, or unverified formula variants.
- Automatic splitting, multi-book batch scheduling, or documents above the effective limits.
- Translated EPUB as a first-release requirement; existing source-language preview functionality is retained.
- A separate translator, renderer, database, task queue, persistent cross-task recognition archive, or pluggable recognition-provider framework.
- Hosted commercial operation, billing, multi-user token management, and commercial compliance workflows.
- Guaranteed remote cancellation/deletion, guaranteed zero usage after stopping, or unsupported pricing/retention promises.
- Automatic resubmission of uncertain remote work or automatic migration of incompatible native-extraction checkpoints.
- Changes to unrelated input formats, finished-output retention policy, or private historical evidence.
- Live provider calls or real-book uploads merely because this spec is written or published.

## Further Notes

- Product scope and the primary acceptance seam are confirmed. This is the release specification; implementation should proceed through separately approved tracer-bullet child tickets rather than treating the entire release as one context-sized task. Publication does not authorize live recognition or translation calls.
- This follows the reconstruction work merged in PR #17 and the completed source-language PDF, EPUB, and acceptance-package issues #14, #15, and #16. Those artifacts do not establish translated whole-book quality.
- Official API reference: https://mineru.net/apiManage/docs. The standard service's documented per-file limits informed the application ceiling. The probe's five-page selection was a local restriction, not a provider limit; conflicting multi-file batch documentation is not a reason to build batching into this single-book release.
- Provider document retention/deletion, callable cancellation, pricing, and submission idempotency remain unverified. They are recorded limitations, not additional approval workflows for the agreed personal-use scope. Incomplete-transfer recovery must remain honest about what the verified contract permits.
- The 198-page reference is a candidate acceptance book, not an authorized live submission. Obtain separate explicit approval for every new live recognition/translation test; a prior five-page probe authorization is not blanket permission.
- Supporting glossary, architecture decisions, and research/development notes currently exist locally and are not yet committed. This spec is self-contained and must not depend on unpublished local documents for an implementing agent to understand its requirements.
